# Перенос пользовательских полей Битрикс24

Веб-инструмент на PHP для копирования пользовательских полей CRM (`UF_CRM_*`)
с одного портала Битрикс24 на другой через REST API (входящие вебхуки).

Поддерживаемые сущности: **Лиды, Сделки, Контакты, Компании, Предложения**.

## Возможности

- Загрузка списка пользовательских полей с портала-источника и сравнение
  с приёмником (показывает, какие поля уже существуют).
- Выбор конкретных полей для переноса через интерфейс (по умолчанию отмечены
  отсутствующие на приёмнике).
- Перенос типа, кода, названий, сортировки, обязательности, множественности,
  настроек и значений списочных полей (`enumeration`) вместе с XML_ID.
- Опциональное обновление свойств уже существующих полей.
- Журнал переноса с результатом по каждому полю.
- Троттлинг запросов (соблюдение лимита ~2 запроса/сек Битрикс24).

## Требования

- PHP 7.4+ с расширениями `curl` и `json`
- Любой веб-сервер (Apache, nginx + php-fpm) или встроенный сервер PHP

## Установка и запуск

1. Скопируйте папку проекта на сервер или запустите локально:

   ```bash
   php -S localhost:8000 -t bitrix-field-migrator
   ```

2. На **обоих** порталах создайте входящий вебхук:
   *Разработчикам → Другое → Входящий вебхук*, права — **CRM (crm)**.
   Пользователь вебхука на приёмнике должен иметь право изменять настройки CRM
   (обычно администратор портала).

3. Откройте `http://localhost:8000/`, вставьте URL вебхуков
   (вида `https://portal.bitrix24.ru/rest/1/xxxxxxxx/`), нажмите
   «Проверить» и «Сохранить настройки».

4. Выберите сущность, загрузите поля, отметьте нужные и нажмите
   «Перенести выбранные поля».

## Ограничения и особенности

- Переносятся только **пользовательские** поля (`UF_CRM_*`). Стандартные поля
  (Название, Сумма, Телефон…) существуют на любом портале и созданию через
  REST не подлежат.
- Поля типов `crm_status`, `crm`, `iblock_element`, `iblock_section` создаются,
  но их настройки ссылаются на объекты исходного портала (справочники,
  инфоблоки) — после переноса проверьте привязки на приёмнике. В интерфейсе
  такие поля помечены знаком «!».
- При включённой опции «Обновлять существующие» у полей на приёмнике
  обновляются названия и настройки, но **значения списков не изменяются** —
  иначе REST API Битрикс24 может удалить/задвоить элементы списка.
- Соответствие полей определяется по коду `FIELD_NAME`. Поля с автогенерируемым
  кодом (`UF_CRM_1612345678`) переносятся с тем же кодом.
- Инструмент переносит **описания полей**, а не данные сделок/лидов. Перенос
  самих записей — отдельная задача (crm.deal.list → crm.deal.add).

## Безопасность

- `config.json` содержит URL вебхуков, дающих полный доступ к CRM порталов.
  **Не выкладывайте папку в публичный доступ без авторизации** — закройте её
  HTTP Basic Auth (пример для Apache в `.htaccess`) или запускайте локально.
- Запретите раздачу `config.json` веб-сервером (в комплекте `.htaccess`
  для Apache уже делает это).

